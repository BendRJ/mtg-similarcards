# BFF API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the fixture-backed FastAPI app with a Postgres-backed backend-for-frontend serving card autocomplete, card detail, printings, similar cards, card images, and set browsing.

**Architecture:** `backend.py` builds the app (CORS, 503 handler, routers). A request-scoped dependency yields a `dict_row` cursor. All SQL lives in one module, `queries.py`: plain functions that take a cursor and return dicts. Thin routers in `routers/` validate params, call `queries`, map `None` to 404, and pin shapes with Pydantic `response_model`s.

**Tech Stack:** Python 3.13, FastAPI 0.141 (sync `def` handlers), psycopg 3 (sync), pgvector `<=>`, unittest + `fastapi.testclient`.

**Spec:** `docs/superpowers/specs/2026-10-31-bff-api-design.md`

## Global Constraints

- No new dependencies. `TestClient` uses `httpx`, already installed via `fastapi[standard]`.
- Route handlers are `def`, never `async def`.
- Never `SELECT *`; never select `embedding` or `card_images.image` except in the image route.
- All SQL values are parameterised. Only constants are interpolated into SQL strings.
- psycopg errors → HTTP 503 `{"detail": "Database unavailable."}`. Exception text never reaches the client; log it with `logger.exception`.
- One card = `COALESCE(oracle_id, id)` (written `card_key` below). "Most recent printing" = `released_at DESC NULLS LAST`, then collector order.
- Collector order: numeric part first, then the raw string, so "2" < "10" < "10a".
- Limits: autocomplete `q` min length 2, `limit` default 10, max 25. Similar `limit` default 12, max 50.
- `colors` param: comma-separated from `W U B R G C`, uppercase. Invalid → 422.
- CORS: explicit allow-list from env `CORS_ORIGINS` (comma-separated), default empty, never `*`, `allow_methods=["GET"]`.
- Tests run with `make run-all-tests` (`PYTHONPATH=src … unittest discover -s tests`). DB-backed tests skip when no Postgres is reachable.
- Work on branch `feature/bff-api`. Never stage `docs/index.md` or `docs/api-database-wiring.md` (the user's uncommitted edits). Commit messages carry no AI attribution.

## Review Focus

1. **`GET /cards/autocomplete` shadowed by `/cards/{card_id}`.** It must reach autocomplete, not 404 as a card id. Pinned in Task 4.
2. **`%`, `_` or `\` in the autocomplete text.** These match literally, not as wildcards. Pinned in Task 4.
3. **Set code case:** `/sets/MH3/cards` and `/sets/mh3/cards` return the same cards. Pinned in Task 7.
4. **Collector numbers like `10a`, `★5`, or NULL** sort without errors and in a sensible order. Pinned in Task 7.
5. **Cards with NULL `colors`** (double-faced) are excluded when a color filter is set and included without one. Pinned in Task 7.

```sql
) t
ORDER BY (t.name ILIKE %(prefix)s) DESC, t.name
LIMIT %(limit)s
```

**Interfaces:**
- Consumes: `get_card` (Task 3) for the unknown-id 404; `SimilarCard`.
- Produces: `queries.similar_cards(cur, card_id: str, limit: int) -> list[dict[str, Any]] | None`. It returns `None` when no printing of the card has an embedding, and keys = `SimilarCard` fields otherwise.

`queries.py` loads the SQL file at import time, as `image_pipeline.py` does (`Path(...).read_text()`, cast to `LiteralString`). The file uses named placeholders `%(card_id)s` and `%(limit)s`. `SUMMARY_COLUMNS` etc. are written out in the file, because it can't import Python constants; keep them in sync.

```sql
WITH ref AS (
  SELECT COALESCE(oracle_id, id) AS card_key, embedding FROM cards
  WHERE COALESCE(oracle_id, id) = (SELECT COALESCE(oracle_id, id) FROM cards WHERE id = %(card_id)s)
    AND embedding IS NOT NULL
  ORDER BY released_at DESC NULLS LAST LIMIT 1
), candidates AS (
  SELECT DISTINCT ON (COALESCE(c.oracle_id, c.id)) <summary columns>,
         c.embedding <=> ref.embedding AS distance
  FROM cards c CROSS JOIN ref
  WHERE c.embedding IS NOT NULL AND COALESCE(c.oracle_id, c.id) <> ref.card_key
  ORDER BY COALESCE(c.oracle_id, c.id), c.released_at DESC NULLS LAST, <collector order>
)
SELECT * FROM candidates ORDER BY distance LIMIT %(limit)s;
```

`similar_cards` first runs a cheap existence check (`SELECT 1 … WHERE card_key matches AND embedding IS NOT NULL`) and returns `None` if nothing is found. That separates "no embedding" from "embedded, but no other cards" (`[]`).

  - `app.backend.routers.sets.router: APIRouter(prefix="/sets", tags=["sets"])`.

Card filter and dedup for `get_set_cards`. Python splits `colors` into `colored = [x for x in colors if x != "C"]` and `colorless = "C" in colors`, and binds `filtered = colors is not None`. With no filter, `colored` is `None` and `colorless` is `False`. Cards with NULL `colors` evaluate to NULL in both branches, so any filter excludes them:

```sql
SELECT * FROM (
  SELECT DISTINCT ON (<CARD_KEY>) <SUMMARY_COLUMNS>, c.collector_number
  FROM cards c
  WHERE lower(c.set_code) = lower(%(set_code)s)
    AND (%(filtered)s IS FALSE
         OR c.colors && %(colored)s::text[]
         OR (%(colorless)s AND c.colors = '{}'))
  ORDER BY <CARD_KEY>, <COLLECTOR_ORDER>
) t ORDER BY <COLLECTOR_ORDER on t>
```
