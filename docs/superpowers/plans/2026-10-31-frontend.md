# Card Discovery Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A React card discovery UI (home with search + color buttons, color, card and set pages) on top of the BFF API, running both in local dev and in Docker.

**Architecture:**
- **Backend:** two additions, a Scryfall `image_url` fallback and `GET /cards/random`.
- **Frontend:** a Vite + React + TypeScript SPA in `frontend/`. It calls the API through relative paths only (`/cards`, `/sets`).
  - In dev, Vite's proxy forwards those paths to `127.0.0.1:8000`.
  - In Docker, an nginx container serves the build and forwards them to `app` over the Compose network.
- **Ports:** everything is published on loopback only.

**Tech Stack:**
- Python 3.13, FastAPI, psycopg 3, unittest (backend).
- React 19.3.1, react-router 8.5.1, Vite 8.3.5, TypeScript 7.0.2, Vitest 5.0.5 + jsdom + Testing Library (frontend).
- nginx 1.31.8, node 26.13.0 (Docker).

**Spec:** `docs/superpowers/specs/2026-10-31-frontend-design.md`. The visual reference is `docs/superpowers/specs/2026-10-31-frontend-mockups.html`.

## Global Constraints

- **npm packages:** only the approved list, at these exact versions (no `^`/`~`). Anything else needs the user's confirmation first.
  - runtime: `react` 19.3.1, `react-dom` 19.3.1, `react-router` 8.5.1
  - dev: `vite` 8.3.5, `@vitejs/plugin-react` 6.1.2, `typescript` 7.0.2, `@types/react` 19.3.0, `@types/react-dom` 19.3.0, `vitest` 5.0.5, `jsdom` 30.1.3, `@testing-library/react` 16.3.3, `@testing-library/user-event` 14.6.8
- **Docker base images**, pinned: `node:26.13.0-alpine3.24` and `nginx:1.31.8-alpine3.24`.
- **Frontend routes are singular** (`/card/:id`, `/set/:code`, `/color/:c`); **API paths are plural** (`/cards…`, `/sets…`). Only API prefixes are proxied. Never add a frontend route starting with `/cards` or `/sets`.
- **Frontend fetches use relative URLs** only. User text in a URL always goes through `encodeURIComponent` / `URLSearchParams`.
- **Ports:** all published on `127.0.0.1`: API 8000, frontend 8080, postgres 5432.
- **Backend:** same rules as the BFF plan.
  - Sync `def` handlers.
  - No `SELECT *`.
  - Values are parameterised; only constants are interpolated into SQL.
  - TDD, with real-Postgres SQL tests via `tests/db_fixtures.py`.
- **Similar cards:** `similar_cards.sql` mirrors the constants in `queries.py`. Any change to `IMAGE_URL`, `PLAYABLE` or the color rule is made in both.
- **Footer text, exactly:** "Card data and images via Scryfall. Magic: The Gathering is © Wizards of the Coast."
- **Copy, exactly:**
  - "Search cards or sets…"
  - "No cards or sets found"
  - "Similar cards aren't available for this card yet"
  - "Couldn't reach the card database. Try again."
  - Color titles "Random white/blue/black/red/green/colorless cards"
- **Search dropdown:** opens at ≥ 2 characters, with a debounce of 150 ms. It shows up to 10 cards and up to 5 sets. Sets of type `token`, `memorabilia` and `minigame` are never shown.
- **Branch:** `feature/frontend`. Commit messages carry no AI attribution.
- **Test commands:**
  - Backend: `make run-all-tests`.
  - Frontend: `make frontend-test` (`npm test` in `frontend/`, i.e. `vitest run`).

## Review Focus

1. **Deep link or reload on `/card/<id>` or `/set/mh3` in Docker.** nginx must serve `index.html`, not 404. Pinned in Task 9.
2. **Search text with `&`, `#`, `%`, `/` or spaces.** It reaches the API intact, encoded. Pinned in Task 4.
3. **Clicking a similar card or printing on the card page** (same route, new `:id`). The page must refetch and drop the old card's data, not show a mix. Pinned in Task 7.
4. **Card images that are `null` or fail to load** (Scryfall 404). Show the name placeholder, never a broken-image icon. Pinned in Task 6.
5. **A hand-edited `?colors=xyz` or lowercase `/color/r` URL.** Lowercase works. Invalid letters are dropped silently instead of producing a 422 error page. Pinned in Tasks 6 and 8.

**Interfaces:**

### Task 4: API client, colors, set matching, stale-safe hook

**Files:**
- Create: `frontend/src/types.ts`, `api.ts`, `lib/colors.ts`, `lib/sets.ts`, `lib/useAsync.ts`
- Tests: `frontend/src/api.test.ts`, `lib/colors.test.ts`, `lib/sets.test.ts`, `lib/useAsync.test.tsx`

**Interfaces:**
- `types.ts` mirrors `src/app/backend/models.py` exactly: `CardSummary`, `CardDetail`, `Printing`, `SimilarCard`, `SetSummary` (every nullable field as `T | null`).
- `class ApiError extends Error { status: number; detail: string | null }`. A network failure is thrown as `ApiError` with `status: 0`.
- `api` object. Every method takes an optional `signal?: AbortSignal` and returns a `Promise`:
  - `autocomplete(q: string, limit = 10)` → `CardSummary[]`
  - `card(id: string)` → `CardDetail`
  - `printings(id)` → `Printing[]`
  - `similar(id, limit = 12)` → `SimilarCard[]`
  - `sets()` → `SetSummary[]`. It is cached in-module after the first successful call.
  - `setCards(code, colors: Color[])` → `CardSummary[]`. It omits `colors` when the list is empty.
  - `random(colors: Color[], limit = 100)` → `CardSummary[]`
- `lib/colors.ts`:
  - `type Color = "W"|"U"|"B"|"R"|"G"|"C"`
  - `COLORS: Color[]` in WUBRGC order
  - `COLOR_NAMES: Record<Color, string>` (white, blue, black, red, green, colorless)
  - `parseColor(s: string): Color | null` (case-insensitive)
  - `parseColorList(s: string | null): Color[]`: drops invalid letters and duplicates, returns WUBRGC order
  - `serializeColors(c: Color[]): string`: comma-joined in WUBRGC order
- `lib/sets.ts`: `matchSets(sets: SetSummary[], query: string, limit = 5): SetSummary[]`. It matches case-insensitively when the name contains the query or the code starts with it, excludes `set_type` in `token`/`memorabilia`/`minigame`, and keeps the input order (the API already sends newest first).
- `lib/useAsync.ts`: `useAsync<T>(load: (signal: AbortSignal) => Promise<T>, deps: unknown[]) → { status: "loading" | "ok" | "error", data: T | null, error: ApiError | null, reload: () => void }`. It aborts the previous load whenever `deps` change or the component unmounts. A result from an aborted load is never applied.
